# Flask template

Простий стартовий шаблон Flask із Flask-Admin, SQLite, статтями, категоріями та завантаженням зображень. Python 3.11+.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
cp .env-example .env
# Windows: copy .env-example .env
python -c "import secrets; print(secrets.token_hex(32))"
```

Запишіть згенероване значення в `SECRET_KEY` у `.env`. Без секретного ключа застосунок навмисно не запускається. Далі:

```bash
flask --app app init-db
flask --app app create-admin
flask --app app run --debug
```

Головна: <http://127.0.0.1:5000/>. Адмінпанель: <http://127.0.0.1:5000/admin/>.

`create-admin` запитує логін, email і пароль (від 8 символів); пароль хешується. **Усі облікові записи в цьому шаблоні — адміністратори.** Публічної реєстрації немає. Не додавайте її без окремого обмеження адміністративного доступу.

## Структура

- `app.py` — фабрика `create_app`, налаштування розширень і обробники помилок.
- `extensions.py` — SQLAlchemy, Flask-Login і CSRFProtect без прив'язки до конкретного app.
- `config.py` — конфігурація з `.env`; шляхи не залежать від робочої папки.
- `models.py` — ORM-моделі та методи роботи з паролями.
- `views.py` — один Blueprint для наявних публічних маршрутів, входу й медіафайлів.
- `admin.py` — захищені CRUD-сторінки Flask-Admin.
- `cli.py` — ініціалізація БД, створення адміністратора та заміна пароля.
- `utils.py`, `recaptcha.py`, `context.py` — невеликі допоміжні функції.
- `templates/`, `static/` — шаблони й статичні ресурси.
- `instance/` — локальна база; не потрапляє у Git.
- `media/` — контентні зображення в корені проєкту; файли не потрапляють у Git.

Окремі repository/service/DTO-шари для цього стартового шаблону не потрібні.

## Дані та налаштування

За замовчуванням база створюється в `instance/data.db`, зображення — в `media/`. `init-db` створює відсутні таблиці й не видаляє дані. Він не є інструментом міграції схеми: при подальших змінах моделей використовуйте міграції.

Іншу базу можна задати через `DATABASE_URL` (для PostgreSQL також установіть відповідний DBAPI-драйвер). Ліміт запиту — 8 MiB, дозволені PNG, JPEG, GIF і WebP. Перевіряється фактичний формат зображення; файли зберігаються з унікальними іменами. Зображення статей зберігаються в `media/posts/<post_id>/` і доступні за `/media/posts/<post_id>/...`. Завантаження доступне після першого збереження статті. Каталог зображень в адмінці доступний для перегляду; довільне редагування файлових шляхів вимкнено.

Текст статті — **HTML від довіреного адміністратора**, який відображається без екранування. Редактор — звичайне текстове поле з вибором і завантаженням зображень; старий CKEditor 4 прибрано. Для публічного введення HTML перед збереженням потрібна санітизація.

Вхід, вихід, адміністративні форми й завантаження мають CSRF-захист. Вихід виконується через POST. reCAPTCHA необов'язкова: укажіть обидва `GOOGLE_RECAPTCHA_*` ключі або залиште обидва порожніми. Коли `DEBUG=True`, віджет і серверна перевірка reCAPTCHA вимкнені; ключі для цього режиму не потрібні. Пошук Google вмикається через власний `GOOGLE_CSE_ID`; чужі ідентифікатори не вбудовані.

## Моделі й база даних

| Модель | Таблиця |
| --- | --- |
| `Post` | `posts` |
| `Image` | `images` |
| `User` | `users` |
| `Category` | `categories` |

`Post.category_id` посилається на `categories.id`. `Image.post_id` зберігає ідентифікатор статті, до якої завантажено зображення; зображення залишаються доступними після видалення статті. Шаблони й адміністративні маршрути використовують назви Post/Image: `/admin/post/`, `/admin/image/`, `/admin/category/`.

Міграції наразі не створюються. `init-db` не перейменовує старі таблиці чи колонки. Для початку без попередніх даних використайте нову порожню базу; перенесення наявної бази на цю схему потрібно виконувати окремо зі збереженням резервної копії.

Для заміни пароля наявного користувача в таблиці `users`:

```bash
flask --app app set-password existing_username
```

Старі паролі у відкритому тексті не приймаються. Демонстраційна база й контентні зображення не відстежуються Git. Файли з попередніх `static/img/articles/` та `instance/uploads/` перенесені до `media/`; нові завантаження використовують підпапку `posts/`. Посилання в раніше збереженому контенті автоматично не змінюються.

Параметри `APP_FOLDER`, `DOMEN`, OAuth і Facebook зі старого прикладу конфігурації більше не використовуються. Endpoint-и публічних маршрутів мають префікс `main.`; публічні адреси сторінок збережені.

## Production

Не використовуйте вбудований сервер Flask і debug-режим у production. Наприклад, для Linux:

```bash
python -m pip install gunicorn
gunicorn --bind 127.0.0.1:8000 'app:create_app()'
```

Також доступний WSGI-вхід `main:app`; імпорт `main.py` не запускає сервер. У `.env` задайте `DEBUG=false` і `SESSION_COOKIE_SECURE=true`, якщо сайт працює через HTTPS. Базу, секретний ключ і завантаження зберігайте між розгортаннями та резервуйте.

## Перевірки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
ruff check .
ruff format --check .
```

Тести використовують окрему SQLite-базу в пам'яті й тимчасові файли. Перевіряють доступ до адмінки, хешування паролів, CSRF, CRUD статей, категорії, пагінацію та завантаження. GitHub Actions запускає ці перевірки на Python 3.11–3.13.
