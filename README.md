# Flask template

Простий стартовий шаблон Flask із Flask-Admin, SQLite, статтями, категоріями та завантаженням зображень. Python 3.11+.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
cp .env-example .env
# Windows: copy .env-example .env
python -c "import secrets; print(secrets.token_hex(32))"
```

Запишіть згенероване значення в `SECRET_KEY` у `.env`. Без секретного ключа застосунок навмисно не запускається. Далі:

```bash
flask --app app init-db
flask --app app create-admin
flask --app app run --debug
```

Головна: <http://127.0.0.1:5000/>. Адмінпанель: <http://127.0.0.1:5000/admin/>.

`create-admin` запитує логін, email і пароль (від 12 символів); пароль хешується. **Усі облікові записи в цьому шаблоні — адміністратори.** Публічної реєстрації немає. Не додавайте її без окремого обмеження адміністративного доступу.

## Структура

- `app.py` — фабрика `create_app`, налаштування розширень і обробники помилок.
- `extensions.py` — SQLAlchemy, Flask-Login і CSRFProtect без прив'язки до конкретного app.
- `config.py` — конфігурація з `.env`; шляхи не залежать від робочої папки.
- `models.py` — ORM-моделі та методи роботи з паролями.
- `views.py` — один Blueprint для наявних публічних маршрутів, входу й медіафайлів.
- `admin.py` — захищені CRUD-сторінки Flask-Admin.
- `cli.py` — ініціалізація БД, створення адміністратора та заміна пароля.
- `utils.py`, `recaptcha.py`, `context.py` — невеликі допоміжні функції.
- `templates/`, `static/` — шаблони й статичні ресурси.
- `instance/` — локальна база й завантажені зображення; не потрапляють у Git.

Окремі repository/service/DTO-шари для цього стартового шаблону не потрібні.

## Дані та налаштування

За замовчуванням база створюється в `instance/data.db`, зображення — в `instance/uploads/`. `init-db` створює відсутні таблиці й не видаляє дані. Він не є інструментом міграції схеми: при подальших змінах моделей використовуйте міграції.

Іншу базу можна задати через `DATABASE_URL` (для PostgreSQL також установіть відповідний DBAPI-драйвер). Ліміт запиту — 8 MiB, дозволені PNG, JPEG, GIF і WebP. Перевіряється фактичний формат зображення; файли зберігаються з унікальними іменами. Завантаження доступне після першого збереження статті. Каталог зображень в адмінці доступний для перегляду; довільне редагування файлових шляхів вимкнено.

Текст статті — **HTML від довіреного адміністратора**, який відображається без екранування. Редактор — звичайне текстове поле з вибором і завантаженням зображень; старий CKEditor 4 прибрано. Для публічного введення HTML перед збереженням потрібна санітизація.

Вхід, вихід, адміністративні форми й завантаження мають CSRF-захист. Вихід виконується через POST. reCAPTCHA необов'язкова: укажіть обидва `GOOGLE_RECAPTCHA_*` ключі або залиште обидва порожніми. Пошук Google вмикається через власний `GOOGLE_CSE_ID`; чужі ідентифікатори не вбудовані.

## Перехід зі старої версії

1. Зробіть резервну копію своєї бази й файлів. Демонстраційна база та завантаження більше не відстежуються Git; локальні копії при цій зміні залишено на місці.
2. Для використання попередньої бази вкажіть її абсолютний шлях у `.env`, наприклад `DATABASE_URL=sqlite:////srv/myapp/db/data.db`. Або перенесіть її в `instance/data.db`.
3. Назви таблиць і колонок збережено. Старі паролі у відкритому тексті більше не приймаються. Задайте новий пароль для кожного наявного адміністратора:

   ```bash
   flask --app app set-password existing_username
   ```

4. Залиште старі файли в `static/img/articles/`, якщо база на них посилається. Нові завантаження використовують `/media/...`.
5. Старі параметри `APP_FOLDER`, `DOMEN`, OAuth і Facebook у прикладі конфігурації більше не використовуються. Внутрішні endpoint-и маршрутів тепер мають префікс `main.`; публічні адреси сторінок збережені.

## Production

Не використовуйте вбудований сервер Flask і debug-режим у production. Наприклад, для Linux:

```bash
python -m pip install gunicorn
gunicorn --bind 127.0.0.1:8000 'app:create_app()'
```

Також доступний WSGI-вхід `main:app`; імпорт `main.py` не запускає сервер. У `.env` задайте `DEBUG=false` і `SESSION_COOKIE_SECURE=true`, якщо сайт працює через HTTPS. Базу, секретний ключ і завантаження зберігайте між розгортаннями та резервуйте.

## Перевірки

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
ruff check .
ruff format --check .
```

Тести використовують окрему SQLite-базу в пам'яті й тимчасові файли. Перевіряють доступ до адмінки, хешування паролів, CSRF, CRUD статей, категорії, пагінацію та завантаження. GitHub Actions запускає ці перевірки на Python 3.11–3.13.
